# CaPCL: Caption-Preserved Continual Learning for Text-to-Image Retrieval

### ECCV 2026

[![Python](https://img.shields.io/badge/Python-3.12-blue.svg)](https://www.python.org/)
[![PyTorch](https://img.shields.io/badge/PyTorch-2.7%2B-orange.svg)](https://pytorch.org/)

Fine-tuning a text-to-image retrieval model on new domains can degrade its
performance on previously learned data. CaPCL mitigates this forgetting by
using captions generated by the model to preserve its language grounding
while learning each new task. The framework supports continual training and
evaluation with full fine-tuning or LoRA.

## 🚀 Quickstart

### 📋 Requirements

- CUDA-capable GPU
- One of the following:
  - Docker with the [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)
  - Python 3.12 and [uv](https://docs.astral.sh/uv/)

### Clone the repository

```bash
git clone https://github.com/NEC-N-SOGI/CaPCL.git
cd CaPCL
```

### Configure directories

`src/capcl/directory_settings.json` tells CaPCL where to find
dataset configurations and images, and where to save experiment results. It
is read whenever `capcl` is imported and is required for both
Docker and native execution. The file is ignored by Git so each machine can
keep its own paths.

Create it from the provided template:

```bash
cp src/capcl/directory_settings_sample.json \
   src/capcl/directory_settings.json
```

Each key contains one or more named machine profiles:

```json
{
  "config_path": {
    "local": "/capcl/experiments/configs/dataset/",
    "server1": "/path/to/capcl/experiments/configs/dataset/"
  },
  "data_path": {
    "local": "/capcl/data/share/",
    "server1": "/path/to/data/"
  },
  "result_path": {
    "local": "/capcl/experiments/results/local/",
    "server1": "/path/to/results/"
  }
}
```

| Key           | Description                               |
| ------------- | ----------------------------------------- |
| `config_path` | Dataset configuration directory           |
| `data_path`   | Image root                                |
| `result_path` | Checkpoints, logs, and evaluation metrics |

The `--machine` argument selects a profile name; its default value is
`local`. The sample paths use `/capcl/...`, which is the repository
mount point inside the Docker container. For native execution, replace them
with absolute paths on the host machine.

For example, select the `server1` paths with:

```bash
uv run python src/capcl/tasks/learner.py \
  --machine server1 \
  ...
```

### Run the sample

The example generates 72 shape images and runs caption generation, LoRA
training, and retrieval evaluation for three sequential tasks. Choose either
Docker or a native installation. Results are saved to
`experiments/results/local/`.

#### Docker

Build the image and run the example:

```bash
make build.gpu
make run.gpu command="bash experiments/sample/run_sample.sh"
```

To use a specific GPU:

```bash
make gpu=0 run.gpu command="bash experiments/sample/run_sample.sh"
```

#### Native installation

After changing `directory_settings.json` to host paths, install the
dependencies and run:

```bash
uv sync
bash experiments/sample/run_sample.sh
```

## 🗂️ Preparing your own data

### Step 1: Create one JSON file per split

Each split contains image paths, retrieval texts, and their matches:

```json
{
  "name": "animals_train",
  "images": [
    "/path-to-data-dir/animals/dog.jpg",
    "/path-to-data-dir/animals/cat.jpg"
  ],
  "texts": [
    "a dog on the beach",
    "a cat on a sofa"
  ],
  "txt2img": [[0], [1]]
}
```

`txt2img[i]` contains the image indices matching `texts[i]`. Multiple texts
may point to the same image, and one text may match multiple images. Every
`txt2img` entry must contain at least one valid index into `images`.

The `/path-to-data-dir/` prefix is replaced with the selected profile's
`data_path`.

Repeat this step for every task and split. For the two-task example below,
prepare the following files under `config_path`:

```text
jsons/
├── animals_train.json
├── animals_test.json
├── vehicles_train.json
└── vehicles_test.json
```

### Step 2: Define the continual task sequence

Create one dataset config under `config_path`. This file lists the continual
tasks and points each split to the JSON file created in Step 1:

```json
{
  "task0_animals": {
    "train": "jsons/animals_train.json",
    "test": "jsons/animals_test.json",
    "target_metric": "mrr"
  },
  "task1_vehicles": {
    "train": "jsons/vehicles_train.json",
    "test": "jsons/vehicles_test.json",
    "target_metric": "mrr"
  }
}
```

- `task0_animals` and `task1_vehicles` are task keys.
- `train` and `test` are paths relative to the dataset config.
- Each path must reference a split JSON created in Step 1.
- `target_metric` selects the retrieval metric used for continual-learning
  evaluation.

Training tasks are naturally sorted by their task keys, so this example
learns `task0_animals` before `task1_vehicles`. Use numbered prefixes such as
`task0_`, `task1_`, and `task2_` to make the intended order explicit. Every
training task requires both `train` and `test`.

### Step 3: Run training and evaluation

```bash
uv run python src/capcl/tasks/learner.py \
  --machine local \
  --task_config tasks/capcl/capcl_lora.yaml \
  --model_config models/blip2.yaml \
  --optim_config optim/adamw_lora.json \
  --dataset_path your_dataset.json
```

Paths passed to `--task_config`, `--model_config`, and `--optim_config` are
resolved relative to `experiments/configs/`. For `--dataset_path`, the file
name is resolved directly under the selected `config_path`.

## 🤖 Adding a model

Use `src/capcl/models/siglip2.py` and
`src/capcl/models/blip2.py` as reference implementations.

### Step 1: Implement the model and builder

Create `src/capcl/models/my_model.py`:

<details>
<summary><b>Model implementation template</b></summary>

```python
from typing import Any

import torch

from capcl.dataset import BatchImgTxtOutput
from capcl.models.model import (
    BaseMixin,
    BaseModel,
    ModelBuilder,
    ModelOutput,
)
from capcl.registry_class import registry


class MyModel(BaseModel):
    def forward(
        self,
        batch: BatchImgTxtOutput,
        **kwargs: Any,
    ) -> ModelOutput:
        image_features = ...
        text_features = ...
        dataset_name_tokens = self.tokenizer(
            batch["dataset_names"],
            padding="max_length",
            truncation=True,
            max_length=self.tokenizer.max_len,
            return_tensors="pt",
        ).to(image_features.device)

        return ModelOutput(
            img_feat=image_features,
            txt_feat=text_features,
            caption_tokens=torch.empty(0, device=image_features.device),
            dataset_names=dataset_name_tokens.input_ids.to(torch.int64),
            new_text_label=torch.empty(0, device=image_features.device),
            new_text_logits=torch.empty(0, device=image_features.device),
            gen_txt_feat=torch.empty(0, device=image_features.device),
        )

    def image_captioning(
        self,
        img_tensor: torch.Tensor,
    ) -> tuple[torch.Tensor, torch.Tensor]:
        raise NotImplementedError


@registry.register_model_builder("my_model")
class MyModelBuilder(ModelBuilder):
    def __init__(
        self,
        model_class: str,
        model_type: str,
        target_module_name: str,
        **kwargs: Any,
    ) -> None:
        self._model = MyModel(...)
        self._model.tokenizer = ...
        self._model.temp = 0.07
        self._train_img_processor = ...
        self._eval_img_processor = ...
        self._txt_processor = ...
        self._txt_processor.max_len = 128
        self._img_size = (...)
        self._mixin = BaseMixin()
        self._mixin.img_size = self._img_size
        self._target_module_name = target_module_name
        self._target_modules = self.get_target_modules(target_module_name)
        self._has_lm_head = False

    def get_target_modules(self, target_module_name: str) -> list[str]:
        if target_module_name != "all":
            raise ValueError("target_module_name must be 'all'")
        return self.enable_all_modules()
```

</details>

The model must:

| Requirement          | Description                                                     |
| -------------------- | --------------------------------------------------------------- |
| `forward`            | Accept `BatchImgTxtOutput` and return `ModelOutput`             |
| Retrieval features   | Return normalized `img_feat` and `txt_feat`                     |
| `dataset_names`      | Return token IDs produced from `batch["dataset_names"]`         |
| `model.tokenizer`    | Expose a tokenizer with `pad_token_id` and `max_len`            |
| `model.temp`         | Expose the contrastive temperature                              |
| `image_captioning`   | Required when the retrieval model generates captions            |
| `get_target_modules` | Return valid `model.named_modules()` names when LoRA is enabled |

For a retrieval-only model, keep `use_caption: false`, `w_cap_loss: 0`,
`w_itc_gen_loss: 0`, and `gen_sim_distill: ""` in the task config. A model
used with caption preservation must generate `self.N_GEN_CAPS` captions
during evaluation and return generated-caption features and language-model
outputs required by the selected losses. See
`src/capcl/models/blip2.py` for the complete caption-capable flow.

Set `_has_lm_head = True` when the model has a language-model head.

### Step 2: Import the module

Import the new module in `src/capcl/models/__init__.py` so its
registration decorator runs:

```python
from . import my_model

__all__ = [
    # existing entries...
    "my_model",
]
```

### Step 3: Add a model config

Create `experiments/configs/models/my_model.yaml`:

```yaml
model_class: "my_model"
model_type: "model-variant"
target_module_name: "all"
```

The `model_class` value must match the name passed to
`@registry.register_model_builder`.
Add any model-specific config fields to `ModelConfig` in
`src/capcl/tasks/task_cfg.py`.

### Step 4: Run the model

```bash
uv run python src/capcl/tasks/learner.py \
  --machine local \
  --task_config tasks/ft.yaml \
  --model_config models/my_model.yaml \
  --optim_config optim/adamw_ft.json \
  --dataset_path your_dataset.json
```
